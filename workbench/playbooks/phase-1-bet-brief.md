# P1 Bet Brief — Playbook

**目的**：把"我们在测什么"写成一句可证伪的假设。填不完 = 还没想清楚 = 不许 build。
**AI 怎么做**：把 P0 结论拉过来，逐问引导 PM 填。每问都卡"能不能被证伪 / 是否具体"，不合格就打回重写。填完复述一遍让 PM 确认。
**绑定 skill**：用 `epic-hypothesis` 把第 ① 问写成 if/then 可验证结构（做什么 → 谁 → 期望结果 → 怎么验）；框架不清时用 `problem-statement`。
**产物**：`bets/<slug>/01-bet-brief.md`（用下面模板）

---

```
OPPAYA BET BRIEF
产品名：____ · 负责人：____ · 日期：____

① 我们在测什么假设？
   我们相信：[具体用户类型] 会因为 [具体原因] 做 [具体行为]。
   （一句话，能被证伪。不能是"用户会喜欢这个产品"。）

② 我们的目标用户是谁？
   不是"K-pop 粉丝"，是"在 [哪个平台] 上发过 [什么内容] 的人"。
   她在哪里？什么特征让我们能找到她？

③ 上线后 14 天，我们要看到什么行为？
   一个可直接观察的动作，不是问卷、不是感受。
   例：用户在无任何推送下，第 7 天自发回来并完成了 [核心行为]。

④ 看到这个行为 → 怎么做？   没看到 → 怎么做？
   不能写"继续观察"。必须是决定：stop / pivot 到 [具体方向] / 缩 scope 到 [具体调整]。

⑤ 上线前，怎么找到目标用户？
   具体渠道、具体方式、找几个人、谁负责。

⑥ 用户调研最想弄清的一个问题？
   不是"她喜不喜欢产品"，是"关于她的生活，我们现在最不确定的一件事"。
```

## 质检（AI 逐条卡）

- ① 有没有具体用户类型 + 具体原因 + 具体行为三要素？能被证伪吗？
- ② 有没有落到"可被找到"的渠道特征？还停在"粉丝"就打回。
- ③ 是行为不是感受？是"能观察到的一个动作"吗？
- ④ 两个分支都是明确决定吗？出现"再看看"直接打回。
- ⑤⑥ 够具体到明天能执行吗？

## 出口

六问全部合格。**有任何一问填不出来** → 那就是最该去 P2 问用户的地方，标出来，先去访谈。
六问齐了 → 更新 `STATE.md` → 进 P2（或按需先 P3，但假设风险高时强烈建议先 P2）。
