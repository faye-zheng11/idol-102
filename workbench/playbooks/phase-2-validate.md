# P2 验证 / 找信号 — Playbook

**目的**：在正式 build 之前，用**最便宜的探针**逼出残酷真相。不怕失败——失败也是信号；怕的是花大力气做了个学不到东西的 demo（prototype theater）。
**核心原则（Jeff Patton）**：最贵的验证方式就是去写生产级代码。先找最便宜那条路。
**产物**：`bets/<slug>/02-validation.md`

## 本阶段绑定的动作（按顺序）

1. **选探针**：用 `pol-probe-advisor` —— 从 Bet Brief 拿"最不确定、风险最高的假设"，倒推"哪种探针最便宜地能验它"。别按你会做什么选（"我会 Figma 所以做原型"），按要验什么选。
2. **设计探针**：用 `pol-probe` 把探针写成一次性、可丢弃、窄范围、只答一个问题的东西。
3. **跑探针**：
   - 如果探针是**用户访谈** → 用 `discovery-interview-prep` 做提纲，找 5 个真实用户，听生活不讲产品。**访谈铁律**（见 `references/user-research.md`）：
     - **戳破礼貌谎言**：别问"你最喜欢哪一点"（只让自己舒服）。问让人不舒服的：「你完整工作流长什么样？」「这产品哪里最难用？」「你现在最大的痛点是什么？」
     - **看行动，不看话**：判断用户靠他们的行为（Actions），不是嘴上说的（Words）。
   - 其他探针类型（假门 / concierge / 单页落地 / 手工冒烟）→ 按 `pol-probe` 设计执行。
4. **回填**：拿结果回改 Bet Brief 的假设/用户/行为（大概率要改）。用户研究的目的是**指导做减法、逼近 Time to Value**——发现用户只为某个核心价值留下时，果断砍冷门、锁精准 Persona。

### 若探针=访谈，每个受访者（×5）
```
受访者 #n：谁 / 在哪找到 / 日期
- 最近一次相关真实经历？
- 哪里难受 / 卡住？
- 现在怎么凑合解决（替代方案）？
- 反直觉的一句原话：
- 支持还是证伪了哪个假设？
```

## 出口

- 探针跑完，有明确结论：**有信号 / 无信号 / 换探针再试**。
- 无信号也算完成——把它当成省下的 build 成本，记进 `02-validation.md`，可能直接触发 stop/pivot（不用等 P4）。
- 回填了 Bet Brief。
- 更新 `STATE.md`：有信号 → 进 P3；无信号 → 回 P0 或 stop。
