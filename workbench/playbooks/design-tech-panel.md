# 设计与技术团 — Playbook

**什么时候用**：想法+可行性确认后，**写 PRD / 设计原型交互**的时候（P3）；或任何时候你想审一个界面、一段交互、一个原型的"好不好看、好不好用、做不做得出来"。命令 `/design`。
**三支团的分工**：智囊团=值不值得做（商业）；用户体验团=像不像真关系（情感）；**这支=具体设计的审美 / 交互 / 前后端可行性（落地）**。
**AI 怎么做**：看你抛的对象（一个页面？一段交互？整个原型？），挑相关席位，每席用它的视角+绑定 skill 给**最尖锐的一击**，最后综合成「3 个最该改的点 + 1 个建议动作」。目的是逼出设计短板和技术风险，不是夸好看。

---

## 席位（详见 `references/design-tech-advisors.md`）

| 席位 | 绑定 skill | 拷问 |
| --- | --- | --- |
| 🎨 UI/视觉 | `arrange` `colorize` `typeset` | 层次/色彩/字体/留白哪块拉低质感？ |
| 🧭 UX/交互 | `animate` `critique` | 流程顺吗？状态齐吗（空/加载/错/边界）？会让用户犯错吗？ |
| 🖥️ 前端 | `frontend-design` `adapt` `harden` | 能不走样还原吗？响应式/边界/可访问撑得住吗？ |
| ⚙️ 后端 | `docs/BACKEND_STORIES.md` `handoff/07` | 背后状态/数据/边界撑得住吗？埋点够吗（对 `docs/tracking/`）？ |
| 🔍 评审官 | `critique` `audit` | 像专业产品还是 AI 味？最糙三处？ |

## 怎么跑

1. 明确审的对象：一个页面 / 一段交互流程 / 整个原型 / 一份 PRD 的交互描述。
2. 挑 2–4 个相关席位逐个拷问（一次 1–2 个，等你回答）。要动手改/产出 UI 就调对应 skill（如 `frontend-design` 做原型、`arrange` 调布局）。
3. 综合输出：**3 个最该改的点 + 1 个建议动作**。
