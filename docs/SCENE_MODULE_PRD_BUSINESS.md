# Scene 模块 PRD（产品功能版）

> 本文说明 Scene 模块的用户故事、产品意图、页面功能、交互逻辑、动效要求、边界处理和验收标准。  
> 本文不定义接口名称、字段名称、数据表结构或具体技术实现方式，这些由开发根据业务需求自行设计。

## 1. 用户故事

作为一个已经和角色建立联系的用户，  
我希望不只是和他聊天，还能邀请他一起去某个地点、经历一个具体事件，  
这样我会感觉我们之间发生过真正的共同经历，而不是只是在消息里来回对话。

作为一个正在和角色关系推进的用户，  
我希望有时也会被角色邀请去某个地方，  
这样我会感觉他也在推动这段关系，而不是所有互动都由我单方面发起。

作为一个完成 Scene 的用户，  
我希望这段经历能变成一张拍立得留在 Home，  
这样我可以回看我们一起经历过的时刻，并感到关系正在积累时间厚度。

## 2. 产品意图

Scene 是 Idol 102 的共同经历系统。

它不是普通地图，也不是普通聊天换皮。它要让用户完成三个感受：

1. 从“我在聊天”变成“我和角色一起去了某个地方”。
2. 从“消息来回堆叠”变成“我们经历了一个有地点、有事件、有结尾的片段”。
3. 从“聊完就结束”变成“这段经历被保存成拍立得，成为关系记忆”。

Scene 结束后必须留下一个延续信号：

- 生成一条 Scene 记忆，并在 Home 中形成拍立得。

Home 如何按天展示拍立得、当天多个 Scene 如何合并、拍立得详情如何编辑，放在 Home 模块说明。Scene 只负责生成 Scene 记忆和结束时的拍立得卡。

## 3. 模块范围

Scene 模块包含：

1. Scene 地图主页
2. 地点二级页
3. 选角弹窗
4. 用户发起 Scene 的流程
5. 角色 Trigger 发起 Scene 后的前端表现
6. Scene 进入过渡动画
7. Scene 对话页前端体验
8. Active Scene 进行中表现
9. 进行中拦截弹窗
10. Scene 结束和拍立得生成

Trigger 怎么运行、什么条件触发、触发话术和节奏，属于 Trigger 文档。  
Scene 对话的 prompt、开场旁白、角色回复、离场钩子、总结生成，属于 Scene 对话文档。  
本文只说明这些内容触发后，前端应该怎么展示和推进。

## 4. 核心规则

以下规则不能改：

1. Scene 必须在 OB 完成后才开放。
2. Scene 的核心是地点 + 事件 + 角色 + 对话 + 拍立得。
3. 1.0 只开放 Company、Practice Room、Cafe、Mall、Park。
4. Apartment 在 1.0 锁定，不开放。
5. 同一时间只能有 1 个 Active Scene。
6. Active Scene 存在时，用户不能发起其他 Scene。
7. Active Scene 存在时，Trigger 不能再发起新的 Scene 邀请。
8. Active Scene 只锁当前角色普通 Chat，其他角色 Chat 仍可正常聊天。
9. 用户首次进入 Scene、重新进入 Scene、从 Chat/地图恢复进入 Scene，都必须播放进入过渡动画。
10. 从 Home 拍立得进入 Memory Replay 是回顾，不播放进入 Scene 过渡动画。
11. Scene 内只支持纯文本输入。
12. Scene 内不支持图片、语音、电话。
13. 用户发 1 条消息后，必须等角色回复完成后才能继续发下一条。
14. 用户可以主动离开 Scene，不需要二次确认。
15. Scene 有 24 小时有效期。
16. 用户主动离开、24 小时到期、离场钩子自然结束，最终都要生成拍立得。
17. Scene 结束后生成的拍立得要挂到 Home。

## 5. 地点清单

1.0 地图包含 6 个地点，其中 5 个可进入，1 个锁定。

| 地点 | 1.0 状态 | 点击结果 |
| --- | --- | --- |
| Company | 开放 | 进入地点二级页 |
| Practice Room | 开放 | 进入地点二级页 |
| Cafe | 开放 | 进入地点二级页 |
| Mall | 开放 | 进入地点二级页 |
| Park | 开放 | 进入地点二级页 |
| Apartment | 锁定 | 不进入，轻提示 `Not open yet` |

地点名称、地图位置、Apartment 锁定状态可以前端写死。  
地点背景图、事件列表、事件图、邀请文案等内容来自内容配置。

## 6. Scene 地图主页

### 6.1 页面目的

让用户看到可以和角色一起去的地点。

地图不是导航工具，而是关系事件入口。它要让用户感觉自己进入了一片可以发生故事的街区。

### 6.2 页面结构

页面包含：

- 全屏街区夜景地图
- 6 个地点标记
- 地点名气泡
- 地点定位点
- Apartment 锁 icon
- 底部导航 Home / Chat / Scene / Me

Scene tab 高亮。

### 6.3 交互规则

- 点击开放地点，播放地点进入过渡，进入地点二级页。
- 点击 Apartment，展示轻提示：

```text
Not open yet
```

- 如果当前有 Active Scene，地图对应地点展示角色头像 + 提示角标。
- 点击 Active Scene 所在地点，播放进入过渡动画，恢复进入当前 Scene。

### 6.4 视觉和动效要求

- 地图要有夜间街区感，符合整体深夜后台 / 关系故事氛围。
- 地点标记位置稳定，不因屏幕尺寸变化而漂移到不可点区域。
- 点击地点后需要有过渡动画，不能硬切。
- Apartment 锁态要明确，但不能像报错。

## 7. 地点二级页

### 7.1 页面目的

让用户理解这个地点适合发生什么事件，并选择一个想邀请角色一起经历的事件。

### 7.2 页面结构

页面包含：

- 左上返回按钮
- 上半部地点场景图
- 下半部地点信息区
- 地点名称
- 地点介绍
- `Select Event` 小标题
- 事件列表

每个事件项包含：

- 事件名
- `Invite` 按钮

### 7.3 交互规则

- 点击返回，回到地图主页。
- 点击事件的 `Invite`，弹出选角弹窗。
- 地点图、地点介绍、事件列表未加载完成时，使用骨架或占位。

### 7.4 内容来源

- 地点名称、地点介绍、地点场景图：内容配置。
- 事件名称、事件图、邀请文案、Scene 对话上下文：内容配置。
- 内容字段名不在 PRD 定义，由开发和内容配置方式决定。

## 8. 选角弹窗

### 8.1 页面目的

让用户选择这次要邀请哪个已添加角色。

Scene 只允许邀请已添加角色。未添加角色不会出现在选角弹窗中。

### 8.2 页面结构

选角弹窗为 bottom sheet。

包含：

- 顶部拖动条
- 小标签 `INVITE`
- 标题 `Choose a Character`
- 已添加角色网格
- 角色头像
- 角色昵称

### 8.3 排序规则

| 进入来源 | 选角顺序 |
| --- | --- |
| 从某角色 Chat 右上角 Scene 按钮进入 | 该角色排首位，其余按加好友顺序 |
| 从底部导航 Scene tab 进入 | 按加好友先后顺序 |

### 8.4 交互规则

- 点击角色后，跳转该角色 Chat 对话页，进入邀请待发送态。
- 下拉 bottom sheet 或点击空白区域，关闭弹窗，回到地点二级页。
- 如果没有可邀请角色，展示空状态，引导用户去 Chat 添加角色。

## 9. 路径 A：用户发起 Scene

### 9.1 完整流程

用户发起 Scene 的流程如下：

1. 用户进入 Scene 地图。
2. 用户选择地点。
3. 用户选择事件。
4. 用户选择已添加角色。
5. App 跳转到该角色 Chat 对话页。
6. Chat 输入框上方展示地点 / 事件预览条。
7. Chat 输入框内可预填邀请文案。
8. 用户发送邀请。
9. Chat 插入 Scene 邀请卡片。
10. 如果用户保留了邀请文案，Chat 插入用户邀请气泡。
11. 角色回复接受邀请。
12. 角色回复下方出现 `Go Now` 按钮。
13. 用户 24 小时内点击 `Go Now`。
14. 播放进入过渡动画。
15. 创建 Scene。
16. 进入 Scene 对话页。

### 9.2 邀请待发送态

跳转到 Chat 后，该角色对话页进入邀请待发送态。

页面表现：

- 输入框上方出现地点 / 事件预览条。
- 预览条展示 `{location_name} · {event_name}`。
- 预览条右侧有关闭按钮。
- 输入框内可预填该事件的邀请文案。

用户可以：

- 直接发送。
- 修改文案后发送。
- 删除文案，只发送 Scene 邀请卡片。
- 关闭预览条，取消本次 Scene 邀请。

如果用户关闭预览条后只发送普通文本，这条消息不再视为 Scene 邀请。

### 9.3 Scene 邀请卡片

用户发送邀请后，Chat 消息流插入 Scene 邀请卡片。

卡片包含：

- 事件图
- 地点名
- 事件名
- 角标 `SCENE PASS`

如果用户保留了邀请文案，卡片后面还展示一条用户邀请文案气泡。

### 9.4 角色接受和 Go Now

路径 A 中，角色永远接受用户发起的 Scene 邀请，不做拒绝。

角色回复后：

- 角色回复气泡下方出现 `Go Now` 按钮。
- `Go Now` 按钮有效期为 24 小时。
- 用户点击 `Go Now` 后，按钮消失，进入 Scene 过渡动画。
- 24 小时内未点击，邀请过期，按钮消失，展示过期文案。

过期文案：

```text
The invitation has expired.
```

过期后的角色反馈话术由 Scene 对话或 Trigger 相关 prompt 控制，PRD 不定义具体内容。

## 10. 路径 B：角色 Trigger 发起 Scene

### 10.1 说明

Trigger 怎么运行、什么条件触发、什么时候选择哪个角色和事件，不在本文定义。

本文只定义 Trigger 已经触发后，Chat 和 Scene 应该如何表现。

### 10.2 前端表现

Trigger 发起后：

1. 角色在 Chat 中发送一条邀请语音或邀请消息。
2. Chat 中出现 Scene 邀请卡片。
3. 卡片下方展示 `Accept` / `Decline` 按钮。
4. 用户点击 `Accept`。
5. `Accept` / `Decline` 按钮都消失。
6. 播放进入过渡动画。
7. 创建 Scene。
8. 进入 Scene 对话页。

### 10.3 拒绝和过期

用户点击 `Decline`：

- `Accept` / `Decline` 按钮都消失。
- 角色发送拒绝后的回应。
- 不创建 Scene。

用户 24 小时内未操作：

- 邀请过期。
- `Accept` / `Decline` 按钮都消失。
- 可以展示过期文案或角色过期反馈。
- 不创建 Scene。

拒绝回应和过期反馈的具体话术由 Trigger 或 Scene 对话相关 prompt 控制。

## 11. 进入过渡动画

### 11.1 触发时机

以下情况都必须播放进入过渡动画：

- 用户首次进入某个 Scene。
- 用户从 Chat 的 `Go Now` 进入 Scene。
- 用户接受 Trigger 邀请进入 Scene。
- 用户从 Chat 顶部 Scene 进行中条恢复进入 Scene。
- 用户从 Scene 地图 Active Scene 地点恢复进入 Scene。
- 用户在拦截弹窗中点击 `Back to Scene`。

以下情况不播放进入过渡动画：

- 用户从 Home 拍立得进入 Memory Replay 回顾。

### 11.2 动画表现

进入过渡为全屏过渡。

页面包含：

- 背景虚化或暗色场景过渡图
- 大标题
- 副标题

大标题示例：

```text
Heading to {location_name}
```

副标题示例：

```text
Meeting halfway...
```

动画结束后进入 Scene 对话页。

## 12. Scene 对话页

### 12.1 页面目的

让用户在具体地点和事件中与角色进行一段实时文字对话。

Scene 对话页不是 Visual Novel 系统，只是布局和普通 Chat 有明显区别：背景使用事件内容图，页面承载地点、事件和场景氛围。

### 12.2 页面结构

页面包含：

- 事件背景图
- 顶部返回 / 离开入口
- 地点名称
- 事件名称
- 当前角色头像或名称
- 消息流
- 纯文本输入框
- 发送按钮
- 可选动作输入入口

背景图根据事件内容配置获取。

### 12.3 消息表现

- 角色消息和用户消息以 Scene 样式展示，视觉上与普通 Chat 区分。
- 角色回复前展示 `···` 动效。
- 角色回复完成后，输入框恢复可用。
- Scene 内不触发普通 Chat 的语音消息。
- Scene 内不触发普通 Chat 的电话。
- Scene 内不支持图片。

### 12.4 输入规则

- 用户只能输入纯文本。
- 用户每次只能发送 1 条消息。
- 角色回复完成前，输入框和发送按钮不可用。
- 支持动作输入。

动作输入规则：

- 用户可以通过输入框旁的 icon 插入动作格式。
- 用户也可以手动输入括号内容，例如 `(looks away)`。
- 气泡中展示动作内容时，去掉括号。
- 动作内容使用比正文小一号的灰色文字。
- 动作内容不改变消息气泡的基本布局。

### 12.5 对话内容边界

Scene 对话的以下内容由 Scene 对话 prompt 控制：

- 开场旁白
- 角色回复
- 事件上下文
- 离场钩子
- 24 小时到期后的自然收尾
- Scene 总结标题和正文

Scene PRD 不定义这些 prompt 的具体文本，只定义前端体验和流程。

## 13. Active Scene 进行中表现

### 13.1 状态规则

同一时间只能有 1 个 Active Scene。

Active Scene 存在时：

- 用户不能发起其他 Scene。
- Trigger 不能发起新的 Scene 邀请。
- 当前角色普通 Chat 被锁定。
- 其他角色普通 Chat 可以正常使用。

### 13.2 Chat 列表表现

进行中 Scene 的角色，会话卡消息预览显示：

```text
[Scene in progress]
```

该文案可使用粉色或高亮样式。

### 13.3 Chat 对话页表现

当前角色 Chat 对话页：

- 顶部栏下方出现 Scene 进行中条。
- 进行中条展示角色头像、`Scene in progress`、地点名、事件名。
- 点击进行中条，播放进入过渡动画，恢复进入 Scene。
- 底部输入框锁定。

锁定 placeholder：

```text
Scene is in progress
```

### 13.4 Scene 地图表现

地图中 Active Scene 所在地点展示：

- 角色头像
- 提示角标

用户点击该地点后，播放进入过渡动画，恢复进入 Scene。

### 13.5 App 退出和恢复

如果用户在 Active Scene 期间退出 App 或切换页面，回来后默认回到该角色 Chat 页面。

Chat 页面中展示 Scene 进行中条，用户点击后播放进入过渡动画回到 Scene。

## 14. 进行中拦截弹窗

### 14.1 触发时机

当已有 Active Scene 时，用户尝试点击其他地点、其他事件、或发起新的 Scene，需要弹出拦截弹窗。

### 14.2 弹窗内容

正文：

```text
Currently, it's with {character_name} in {location_name}. Want to leave?
```

按钮：

- `Leave Scene`
- `Back to Scene`

弹窗右上角有关闭按钮。

### 14.3 用户选择

| 用户操作 | 结果 |
| --- | --- |
| `Leave Scene` | 结束当前 Scene，生成拍立得，然后允许用户继续新的 Scene 操作 |
| `Back to Scene` | 播放进入过渡动画，恢复当前 Scene |
| 右上角关闭 | 关闭弹窗，停留在当前页面，不结束 Scene |

`Leave Scene` 不需要二次确认。

## 15. Scene 生命周期

### 15.1 创建

以下行为会创建 Scene：

- 用户发起路径中点击 `Go Now`。
- Trigger 路径中点击 `Accept`。

创建后 Scene 进入 active 状态，并开始 24 小时有效期。

### 15.2 结束方式

Scene 可以通过以下方式结束：

| 结束方式 | 说明 | 是否生成拍立得 |
| --- | --- | --- |
| 用户主动离开 | 用户点击 Scene 内离开 icon | 是 |
| 用户在拦截弹窗点击 `Leave Scene` | 结束当前 Scene 后继续其他操作 | 是 |
| 24 小时到期且用户不在 Scene 内 | 系统自动结束 | 是 |
| 24 小时到期但用户正在 Scene 内 | 等待自然收尾或离场钩子结束 | 是 |

### 15.3 主动离开

用户在 Scene 对话页点击离开 icon 后，直接结束 Scene，不弹二次确认。

结束后进入拍立得生成流程。

### 15.4 24 小时到期

Scene 有 24 小时有效期。

- 如果到期时用户不在 Scene 内，Scene 自动结束，并生成拍立得。
- 如果到期时用户正在 Scene 内，不硬切打断用户，由 Scene 对话的自然收尾或离场钩子结束。
- 自然收尾结束后，同样生成拍立得。

## 16. 拍立得生成

### 16.1 生成时机

以下情况都要生成拍立得：

- 用户主动离开 Scene。
- 用户通过拦截弹窗离开 Scene。
- Scene 24 小时到期自动结束。
- Scene 24 小时到期后自然收尾结束。

### 16.2 拍立得卡展示

Scene 结束后，前端立即展示拍立得卡。

拍立得卡包含：

- 顶部 Scene 场景图
- Scene 总结标题
- Scene 总结正文
- 真实日期
- 地点
- `Collect Memory` 按钮

Scene 总结标题和正文由 AI 异步生成。

如果总结还没生成完成，先展示占位文案：

```text
Memory is being written...
```

### 16.3 Collect Memory

用户点击 `Collect Memory` 后：

- 跳转到 Home。
- 定位到对应日期的拍立得位置。
- 对应拍立得卡播放闪烁动效。

如果当天已有其他 Scene，Home 如何合并展示由 Home 模块说明。Scene 只负责生成这一条 Scene 记忆。

## 17. 内容未准备好时的处理

如果内容团队暂时还没给最终地点图、事件图、事件名、邀请文案或 Scene prompt，开发可以先用临时内容搭建页面和流程。

开发期允许：

- 地图图没给：先用夜景占位图。
- 地点图没给：先用地点占位图。
- 事件图没给：先用场景占位图。
- 事件列表没给：先用临时事件。
- 邀请文案没给：先用临时邀请文案。
- Scene prompt 未完成：先用临时回复和占位总结。
- 拍立得总结未生成：展示 `Memory is being written...`。

但上线前，正式内容必须补齐。

## 18. 不希望出现的体验

- OB 未完成时 Scene 可进入。
- Apartment 可进入。
- 用户可以同时开启多个 Scene。
- Active Scene 存在时还能发起新的 Scene。
- 当前角色 Scene 进行中时，还能在该角色普通 Chat 继续聊天。
- 其他角色 Chat 被 Active Scene 错误锁住。
- 重新进入 Scene 时没有过渡动画。
- 从 Home 拍立得回顾时错误播放进入 Scene 动画。
- Scene 内可以发图片、语音或电话。
- 用户发送多条消息导致角色回复顺序错乱。
- 用户离开 Scene 后没有生成拍立得。
- 拍立得生成后没有进入 Home 的入口。
- Scene 结束后 Home 没有对应记忆。
- Trigger 邀请的 `Accept` / `Decline` 点击后按钮仍然留在卡片上。

## 19. 验收标准

### 19.1 地图和地点

- OB 完成后 Scene tab 可进入。
- 地图展示 6 个地点。
- Company、Practice Room、Cafe、Mall、Park 可点击。
- Apartment 显示锁态。
- 点击 Apartment 展示 `Not open yet`。
- 点击开放地点进入地点二级页。

### 19.2 用户发起路径

- 用户可从地图选择地点和事件。
- 用户可从选角弹窗选择已添加角色。
- 从某角色 Chat 进入 Scene 时，该角色在选角中优先展示。
- 选角后跳回该角色 Chat。
- Chat 中出现地点 / 事件预览条。
- 用户发送后插入 Scene 邀请卡片。
- 角色接受后出现 `Go Now`。
- `Go Now` 24 小时有效。
- 点击 `Go Now` 后按钮消失，播放过渡动画并进入 Scene。

### 19.3 Trigger 路径

- Trigger 触发后，Chat 中出现角色邀请消息和 Scene 邀请卡片。
- 卡片展示 `Accept` / `Decline`。
- 点击 `Accept` 后两个按钮都消失。
- 点击 `Accept` 后播放过渡动画并进入 Scene。
- 点击 `Decline` 后两个按钮都消失。
- 24 小时未操作后邀请过期，按钮消失。

### 19.4 Scene 对话页

- Scene 页面展示事件背景图。
- Scene 页面展示地点名和事件名。
- Scene 页面与普通 Chat 布局明显不同。
- 输入框只支持纯文本。
- 不支持图片、语音、电话。
- 用户发送后角色展示 `···`。
- 角色回复完成后输入框恢复。
- 支持括号动作输入，并以小号灰字展示。

### 19.5 Active Scene

- 同一时间只能有 1 个 Active Scene。
- Active Scene 存在时不能发起其他 Scene。
- Active Scene 存在时 Trigger 不能发起新 Scene 邀请。
- 当前角色 Chat 被锁定。
- 其他角色 Chat 不受影响。
- Chat 列表显示 `[Scene in progress]`。
- 当前角色 Chat 顶部展示 Scene 进行中条。
- 点击进行中条播放过渡动画并回到 Scene。
- 地图对应地点展示角色头像和提示角标。
- 点击地图 Active Scene 地点播放过渡动画并回到 Scene。

### 19.6 结束和拍立得

- 用户可点击离开 icon 结束 Scene。
- 离开不需要二次确认。
- 24 小时到期且用户不在 Scene 内时自动结束。
- 24 小时到期但用户在 Scene 内时等待自然收尾。
- 所有结束方式都生成拍立得。
- 拍立得包含场景图、标题、总结、日期、地点。
- 总结未生成时展示 `Memory is being written...`。
- 点击 `Collect Memory` 跳转 Home 对应拍立得位置。
- 对应拍立得卡播放闪烁动效。

## 20. 给开发的自由度

开发可以自行决定：

- 接口如何命名。
- 数据字段如何命名。
- 地点和事件配置如何读取。
- Scene 状态如何存储。
- 过渡动画如何实现。
- Scene 对话消息如何渲染。
- 拍立得生成状态如何轮询或刷新。
- loading、toast、skeleton 的具体组件实现。

但最终体验必须符合本文定义的业务规则、页面表现、交互流程、动效要求和验收标准。
