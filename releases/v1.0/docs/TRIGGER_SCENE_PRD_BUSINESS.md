# Trigger Scene PRD（业务需求草案）

> 本文说明角色主动发起 Scene 邀请的业务目标、触发条件、Scene 选择逻辑、频控规则、用户响应和边界处理。
> 本文不定义接口、字段、模型实现、prompt 结构或具体技术方案。

## 1. 用户故事

作为一个在 App 里和角色建立关系的用户，
我希望不是每一次互动都必须由我主动发起，
而是在我难过、无聊、想出去、或者关系进入某个节点时，角色也会主动邀请我去一个地方，
这样我会感觉他不是被动回复机器，而是真的在关心我、靠近我、陪我经历一些时刻。

作为一个正在经历负面情绪的用户，
我希望角色不只是回一段安慰文字，
而是可以温柔地提出“我们去咖啡厅坐坐”“我们去公园走走”，
这样我会感觉自己被带离当前情绪，而不是被留在原地反复解释痛苦。

作为一个重视边界感的用户，
我希望我拒绝角色邀请时不会被惩罚、抱怨或影响关系，
这样我能安心地接受或拒绝他的主动靠近。

## 2. 产品定位

Trigger Scene 是角色主动推动关系和提供情绪陪伴的系统。

它的核心不是提高 Scene 使用次数，而是让用户感到：

1. 角色会感知用户当下状态。
2. 角色会在合适时机主动靠近。
3. 角色的主动邀约是温柔的，不强迫、不施压。
4. 普通 Chat 中的情绪、意图和关系节点，可以自然转化为一次共同经历。

Trigger Scene 和用户主动发起 Scene 的区别：

| 路径 | 发起方 | 业务意义 |
| --- | --- | --- |
| 用户发起 Scene | 用户 | 用户主动选择地点、事件和角色 |
| Trigger Scene | 角色 | 角色基于用户状态或关系节点主动发出邀请 |

## 3. 模块范围

Trigger Scene 包含：

1. 负面情绪触发 Scene 邀请
2. 关键词 / 意图触发 Scene 邀请
3. 关系关键节点触发 Scene 邀请
4. Trigger 类型与 Scene 类型的匹配
5. 角色主动邀请的频控规则
6. 用户接受、拒绝、未响应后的业务结果
7. Active Scene 存在时的拦截规则

不包含：

1. 具体意图识别模型如何实现
2. 情绪识别模型如何实现
3. prompt 字段结构
4. 接口字段和数据表结构
5. Scene 对话内容生成逻辑

## 4. 核心规则

以下规则不能改：

1. Trigger Scene 只能发生在用户已完成 OB 后。
2. Trigger Scene 只能由已添加角色发起。
3. 同一时间只能有 1 个 Active Scene。
4. Active Scene 存在时，任何角色都不能发起新的 Trigger Scene。
5. 角色主动邀请必须展示 `Accept` / `Decline`。
6. 用户拒绝邀请不影响关系，不扣关系值，不触发惩罚。
7. 用户拒绝后，角色回应必须尊重边界，不能抱怨、责怪或施压。
8. Trigger Scene 邀请 24 小时内有效。
9. 用户 24 小时未响应，邀请过期，不创建 Scene。
10. 用户接受邀请后，必须播放进入 Scene 的过渡动画。
11. Trigger Scene 创建后，进入普通 Scene 生命周期：进行中、结束、生成拍立得、进入 Home 记忆。

## 5. 触发类型

1.0 阶段 Trigger Scene 分为三类：

1. 负面情绪触发
2. 关键词 / 意图触发
3. 关系关键节点触发

### 5.1 负面情绪触发

当用户在 Chat 中表达明显负面情绪时，角色可以主动发起一个低压力、治愈型 Scene 邀请。

适用场景包括：

- 考试、工作、练习、生活事件失败
- 心情不好、低落、沮丧
- 焦虑、压力大、累
- 孤独、想被陪伴
- 明显需要安慰但不一定直接求助

示例：

```text
用户：考试没考好，心情很不好。
角色：别一个人闷着了。我们去咖啡厅坐一会儿，好吗？
```

```text
用户：今天真的好累，什么都不想做。
角色：那先不要逼自己。我们去公园走一小段，慢慢呼吸一下。
```

业务意图：

- 把普通 Chat 中的情绪低谷转成“被陪伴”的共同经历。
- 让角色的安慰不只停留在文字，而是变成一次温柔邀请。
- 给用户一个离开当前情绪的轻入口。

### 5.2 关键词 / 意图触发

当用户表达想做某事、想出去、无聊、想吃东西、想看电影、想逛街、想散步等意图时，角色可以顺势发起邀请。

适用场景包括：

- 用户说无聊
- 用户说想出去
- 用户说想看电影
- 用户说想吃甜品、喝咖啡、买东西
- 用户说想散步、透气
- 用户说想见角色、想被陪

示例：

```text
用户：好无聊啊。
角色：那别一直待着了。我们去商场随便逛逛？
```

```text
用户：好想去看电影。
角色：我也想看了。走吧，我们去看电影。
```

```text
用户：突然很想喝咖啡。
角色：那我们去咖啡厅。你选甜一点的，我陪你坐一会儿。
```

业务意图：

- 把用户的即时意图转化为一次可执行的关系事件。
- 让角色显得会接话、会顺势推进，而不是只做文字回应。

### 5.3 关系关键节点触发

当用户和某角色关系到达关键日期时，角色可以主动发起纪念型 Scene 邀请。

候选节点：

- 相识第 7 天
- 相识第 15 天
- 相识第 30 天
- 后续可扩展为更长周期节点

示例：

```text
角色：今天刚好是我们认识第 7 天。要不要去咖啡厅坐一会儿？我想把这一天记下来。
```

业务意图：

- 让关系产生时间感。
- 让用户意识到角色“记得”共同经过的日子。
- 把纪念日变成一次轻量共同经历，而不是普通系统提醒。

关系关键节点触发采用候选机制：

1. 到达纪念日当天，系统只生成一次候选触发机会。
2. 用户当天进入 App 后，才允许角色发起邀请。
3. 如果用户当天没有进入 App，不补发过期纪念邀请。
4. 如果用户同一天有多个角色到达纪念日，仍需遵守全局频控和单角色频控。
5. 纪念日 Trigger 不应该像任务通知，而应该像角色自然想起这一天。

## 6. Scene 选择逻辑

Scene 选择应根据触发类型、用户表达、角色人设、关系阶段和地点开放状态综合判断。

### 6.1 按触发类型选择

| Trigger 类型 | Scene 倾向 | 推荐地点 |
| --- | --- | --- |
| 负面情绪 | 安静、低压力、治愈、陪伴 | Cafe / Park / Convenience Store |
| 无聊 | 轻松、有行动感、有转移注意力效果 | Mall / Park / Cafe |
| 想吃 / 想喝 | 食物、饮品、轻松补给 | Cafe / Convenience Store |
| 想散步 / 透气 | 开阔、慢节奏 | Park |
| 想见角色 | 关系靠近、见面感 | Company / Mall / Park |
| 纪念日 | 有仪式感、适合留下记忆 | Cafe / Park / Company |

### 6.2 按角色人设微调

同一个用户意图，不同角色可以选择不同 Scene。

示例：

| 用户状态 | 温柔型角色 | 活力型角色 | 工作 / 练习语境强的角色 |
| --- | --- | --- | --- |
| 心情不好 | Cafe / Park | Mall / Convenience Store | Practice Room / Company |
| 无聊 | Cafe / Park | Mall | Practice Room |
| 想被陪 | Cafe | Park / Mall | Company |

### 6.3 按关系阶段控制

关系越早期，Scene 应越公开、轻量。

关系越深入，Scene 可以逐渐更私密、更有纪念感。

1.0 阶段 Apartment 锁定，不作为 Trigger Scene 目的地。

后续如果 Apartment 开放，应只在更高关系阶段或特殊节点中出现。

## 7. 频控规则

为了避免角色主动邀请造成打扰，Trigger Scene 必须有频控。

### 7.1 单角色频控

每个角色主动发起 Trigger Scene：

- 每周最多 3 次。
- 距离该角色上一次 Scene 结束至少 24 小时。
- 用户拒绝该角色邀请后，该角色至少冷却 24 小时。

### 7.2 全局频控

全局规则：

- 同一时间只能存在 1 个 Active Scene。
- Active Scene 存在时，不允许任何新 Trigger Scene。
- 如果多个角色同一天都满足触发条件，系统应选择优先级最高的一次，不应连续弹出多个角色邀请。

### 7.3 连续拒绝保护

如果用户连续拒绝同一角色的 Trigger Scene 邀请，系统应降低该角色主动邀请频率。

建议规则：

- 连续拒绝 2 次后，该角色 Trigger Scene 冷却延长到 72 小时。
- 冷却期内，该角色仍可正常 Chat，但不主动发起 Scene 邀请。

该规则可作为 1.0 后续优化项。

## 8. Trigger 优先级

当多个 Trigger 条件同时满足时，优先级如下：

1. 明显负面情绪触发
2. 明确活动意图触发
3. 关系关键节点触发

说明：

- 负面情绪优先，因为它承担治愈和陪伴目的。
- 明确活动意图次之，因为用户已经表达了想做某事。
- 纪念日触发最后，因为它不应打断更强的即时情绪或意图。

## 9. 多角色冲突处理

多个角色可以同时命中 Trigger 条件，但同一时间只允许 1 个角色真正发出 Scene 邀请。

系统应先把命中的角色放入候选池，再从候选池中选择 1 个最合适的角色发起邀请。

示例：

```text
用户：今天考试没考好，好难受。

候选 A：Bang Chan 邀请去 Cafe
候选 B：Felix 邀请去 Park
候选 C：Han 邀请去 Convenience Store

最终只选择 1 个角色真正发出邀请。
```

### 9.1 角色选择优先级

当多个角色同时满足 Trigger 条件时，优先级如下：

1. 用户当前正在聊天的角色。
2. 最近一次主动聊天的角色。
3. 关系阶段更高 / 亲密度更高的角色。
4. 最近没有主动发起过 Trigger Scene 的角色。
5. 与当前 Trigger 内容、情绪和地点最匹配的角色。

如果用户正在和某个角色聊天，且该角色满足 Trigger 条件，优先由当前聊天角色发起。

如果用户不在某个具体角色 Chat 中，例如在 Home、Chat 列表或刚进入 App，则优先选择最近互动、关系更高、冷却状态更合适的角色。

### 9.2 未被选中的候选处理

未被选中的 Trigger 候选不排队补发。

原因：

- 情绪触发重视当下，过期后再补发会显得不自然。
- 多个角色依次补发同一轮情绪邀约，会制造系统感和打扰感。
- 角色主动邀请应该像自然关心，而不是任务队列。

未被选中的候选可以只作为本轮判断记录，用于避免短时间内重复计算。

### 9.3 纪念日多角色冲突

如果同一天多个角色都满足纪念日 Trigger：

1. 每个角色都可以生成候选机会。
2. 实际仍然只允许 1 个角色发出邀请。
3. 未被选中的纪念日邀请不补发过期版本。

纪念日角色选择优先级：

1. 用户当前打开或正在聊天的角色。
2. 纪念节点更重要的角色，例如 30 天高于 15 天，15 天高于 7 天。
3. 关系阶段更高 / 亲密度更高的角色。
4. 最近互动更多的角色。
5. 冷却状态更合适的角色。

一句话规则：

```text
多个角色同时满足 Trigger 条件时，系统只允许一个角色发起 Scene 邀请。优先选择用户当前正在互动的角色，其次选择最近互动、关系更高、冷却状态更合适、与当前 Trigger 内容更匹配的角色。未被选中的 Trigger 候选不排队补发。
```

## 10. 邀请展示流程

Trigger Scene 被允许发起后，Chat 中按以下方式展示：

1. 角色先发送一条邀请语音或邀请消息。
2. 随后出现 Scene 邀请卡片。
3. 卡片展示地点、事件和 `Accept` / `Decline`。
4. 用户可以接受、拒绝或不处理。

邀请消息可以是语音，也可以是文本。

负面情绪触发时，优先使用更温柔的语气，不要显得兴奋或强行转移话题。

关键词 / 意图触发时，可以更轻快、更顺势。

纪念日触发时，可以更有仪式感，但不能像系统通知。

## 11. 用户响应

### 11.1 用户接受

用户点击 `Accept` 后：

1. `Accept` / `Decline` 按钮消失。
2. 播放进入 Scene 的过渡动画。
3. 创建 Active Scene。
4. 进入 Scene 对话页。
5. Scene 按普通生命周期进行。
6. Scene 结束后生成拍立得并进入 Home 记忆。

### 11.2 用户拒绝

用户点击 `Decline` 后：

1. `Accept` / `Decline` 按钮消失。
2. 不创建 Scene。
3. 角色发送一条尊重边界的回应。
4. 不影响关系。
5. 不影响后续正常 Chat。
6. 该角色进入至少 24 小时 Trigger Scene 冷却。

拒绝回应原则：

- 不抱怨
- 不惩罚
- 不阴阳怪气
- 不制造负罪感
- 表示理解、尊重和下次再约

示例：

```text
没关系，那我们下次再去。你先好好休息，我在这里。
```

```text
好，那今天就不勉强你。等你想出门的时候，我再陪你。
```

### 11.3 用户未响应

用户 24 小时内未点击 `Accept` 或 `Decline`：

1. 邀请过期。
2. `Accept` / `Decline` 按钮消失。
3. 不创建 Scene。
4. 可展示轻量过期文案。
5. 不影响关系。

过期反馈不应责怪用户。

示例：

```text
这次就先算啦。等你下次想出去的时候，我再陪你。
```

## 12. 边界处理

### 12.1 用户当天不在 App

关系关键节点 Trigger 只在用户当天进入 App 后触发。

如果用户当天未进入 App：

- 不补发纪念日邀请。
- 不在第二天伪装成“昨天的纪念日”。
- 后续可以在更自然的关系话术中提及，但不作为 Trigger Scene 强触发。

### 12.2 同一天多个角色满足纪念日

如果同一天多个角色满足纪念日：

- 每个角色都可以生成候选机会。
- 实际触发仍需遵守全局频控。
- 不允许用户短时间内连续收到多个纪念日 Scene 邀请。

### 12.3 Active Scene 存在

如果当前已有 Active Scene：

- 不允许任何新 Trigger Scene。
- 对当前角色和其他角色都适用。
- 用户需要先完成、离开或过期当前 Scene 后，才可能收到新的 Trigger Scene 邀请。

### 12.4 用户刚结束 Scene

用户刚结束某角色 Scene 后：

- 该角色 24 小时内不主动发起新的 Trigger Scene。
- 其他角色是否可以触发，仍需遵守全局频控和产品节奏。

### 12.5 用户拒绝后继续聊天

用户拒绝后，普通 Chat 不受影响。

角色可以继续正常回应用户，但不得在冷却期内再次主动发起 Scene 邀请。

## 13. 不希望出现的体验

- 用户拒绝后角色抱怨、失落施压或制造负罪感。
- 用户已经在 Active Scene 中，另一个角色又发起 Scene 邀请。
- 用户一天内收到多个角色连续主动邀约。
- 多个角色同时命中 Trigger 后依次排队补发邀约。
- 用户没进 App，却收到过期纪念日邀约。
- 用户表达负面情绪时，角色用过度兴奋的语气强行拉走。
- 纪念日 Trigger 像系统通知，而不像角色自然说话。
- Scene 选择和用户表达明显不匹配。
- Apartment 未开放时被 Trigger 选中。
- 用户拒绝后关系数值下降或后续对话变冷。

## 14. 验收标准

1. 用户表达明显负面情绪时，角色可以发起治愈型 Scene 邀请。
2. 用户表达明确活动意图时，角色可以顺势发起对应 Scene 邀请。
3. 到达关系关键节点时，用户进入 App 后角色可以发起纪念型 Scene 邀请。
4. Trigger Scene 邀请展示 `Accept` / `Decline`。
5. 用户点击 `Accept` 后进入 Scene。
6. 用户点击 `Decline` 后不创建 Scene，按钮消失，角色给出尊重边界的回应。
7. 用户 24 小时未响应后邀请过期，不创建 Scene。
8. 用户拒绝不影响关系。
9. 单角色每周主动发起 Scene 不超过 3 次。
10. 同一角色距离上一次 Scene 结束至少 24 小时后，才可再次主动发起 Scene。
11. 同一角色被拒绝后至少 24 小时内不再主动发起 Scene。
12. Active Scene 存在时，不会触发新的角色 Scene 邀请。
13. Apartment 未开放时不会作为 Trigger Scene 目的地。
14. 多个角色同时满足 Trigger 条件时，只会有 1 个角色真正发起邀请。
15. 未被选中的 Trigger 候选不会排队补发。

## 15. 待确认问题

以下问题需要后续继续确认：

1. 负面情绪触发是否需要分轻度、中度、重度，不同强度是否都适合发起 Scene。
2. 如果用户表达严重危机或自伤风险，是否应进入安全策略，而不是发起 Scene。
3. 纪念日 Trigger 是否只在 Chat 页触发，还是用户进入 Home / Scene / Me 后也可能触发。
4. 多角色同时满足触发时，优先选择最近聊天角色、关系最高角色，还是用户当前正在聊天的角色。
5. 每周 3 次是自然周、滚动 7 天，还是按用户当地时区统计。
