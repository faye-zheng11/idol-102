# Chat 模块 PRD（产品功能版）

> 本文说明 Chat 模块的用户故事、产品意图、页面功能、交互逻辑、动效要求、边界处理和验收标准。  
> 本文不定义接口名称、字段名称、数据表结构或具体技术实现方式，这些由开发根据业务需求自行设计。

## 1. 用户故事

作为一个已经完成 OB 的用户，  
我希望能像和真实的人保持联系一样，随时给角色发消息、收到他的回复、听到他的语音，甚至在情绪被触发时接到他的来电，  
这样我会感觉这不是一个一次性剧情，而是一段会继续生长的关系。

作为一个喜欢多个角色的用户，  
我希望能在 Chat 里添加更多成员、看到每个人不同的消息状态，并能给他们发起 Scene 邀约，  
这样我会感觉自己不是只在使用聊天功能，而是在逐渐进入一个有关系、有事件、有记忆的世界。

作为一个希望掌控体验的用户，  
我希望能修改角色昵称、头像、聊天背景、Home 海报，也能清空聊天记录或举报问题内容，  
这样我会感觉这段关系既亲密，也仍然安全可控。

## 2. 产品意图

Chat 不是普通 IM 工具，它是关系延续的主入口。

它要完成四件事：

1. 展示 OB、加好友、Scene 等流程插入到 Chat 中的消息，让用户感觉关系在继续。
2. 支撑日常文本 / 图片聊天，让用户可以持续表达和试探关系。
3. 通过角色语音和角色来电制造更强的陪伴感和情绪峰值。
4. 与 Scene、Trigger、Memory 连接，让聊天不是孤立消息堆叠，而是关系事件的入口和回声。

1.0 阶段不要求完整铺开关系等级系统，但 Chat 必须为后续关系成长留下体验基础：角色会记得、会回应、会邀请、会在不同场景里延续共同经历。

## 3. 模块范围

Chat 模块包含：

1. Chat 列表页
2. Discover Members 加好友页
3. Chat 对话页
4. 角色语音消息
5. 角色来电 Voice Call
6. Scene 邀请在 Chat 中的展示和入口
7. Scene 进行中时 Chat 的锁定与回流
8. Chat Settings
9. 举报弹窗
10. 清空聊天记录

## 4. 核心规则

以下规则不能改：

1. 用户只能主动发送文本、图片、文本 + 图片。
2. 用户不能主动发送语音。
3. 用户不能主动拨打电话。
4. 语音和电话只能由角色侧触发。
5. 角色可以发送文本、语音、电话。
6. 角色文本回复语言跟随用户的 Default Language。
7. 角色语音和电话的声音始终是角色母语。
8. 角色语音和电话必须展示文本内容，文本语言跟随用户的 Default Language。
9. 用户每次只能发送 1 条消息，必须等角色本轮回复完成后才能发送下一条。
10. 图片 + 文字组合算 1 条消息。
11. OB 完成后，首位角色必须出现在 Chat 列表，并展示 OB 流程插入的未读消息。
12. Discover Members 加好友成功后，该角色必须出现在 Chat 列表并带未读开场白。
13. Scene 模块触发的角色消息必须能进入 Chat 消息流。
14. 某角色 Scene 进行中时，该角色普通 Chat 输入框锁定，但其他角色 Chat 不受影响。
15. 清空聊天记录只清空消息显示和该角色聊天内容，不删除会话卡、好友关系、Home 拍立得和角色设置。

## 5. 消息类型

| 类型 | 发送方 | 用户是否可主动触发 | 展示方式 |
| --- | --- | --- | --- |
| 文本 | 用户、角色 | 可以 | 普通聊天气泡 |
| 图片 | 仅用户 | 可以 | 图片气泡，可附带一段文字 |
| 语音 | 仅角色 | 不可以 | 可点击语音条 + 时长 + 文本内容 |
| 电话 Voice Call | 仅角色 | 不可以 | 全屏 App 内模拟来电 + Chat 中生成 `Call Ended` 电话记录 |
| Scene 邀请卡片 | 用户、角色 | 通过 Scene 流程触发 | 地点 / 事件卡片 + 邀请文案 |

### 5.1 用户消息

用户可发送：

- 纯文本
- 纯图片
- 图片 + 文本

用户不可发送：

- 语音消息
- 电话
- 多图
- 文件
- 表情包

### 5.2 角色消息

角色可发送：

- 文本
- 语音
- 电话
- Scene 相关邀请消息

角色 1.0 不发送图片。如果后续内容需要角色图片消息，应另行补充规则。

## 6. 发送和回复流程

普通聊天每一轮按以下流程进行：

1. 用户输入文本 / 图片 / 文本 + 图片。
2. 用户点击发送。
3. 用户消息进入消息流。
4. 输入框和发送按钮暂时禁用。
5. 用户最新消息显示 `Unread`。
6. 角色开始准备回复，状态变为 `Read`。
7. 角色气泡显示 `···` 动效。
8. 角色完整回复出现。
9. 输入框恢复可用。

### 6.1 回复展示

- 角色回复前显示 `···` 打字动效。
- `···` 动效建议持续约 1 秒左右。
- 角色回复是整句一次性出现，不做逐字打字机。
- 角色回复完成前，用户不能继续发下一条。
- AI 返回失败或超时时，用户消息旁展示 retry 图标，用户可点击重试。

### 6.2 发送限制

- 空文本且无图片时，发送按钮不可用。
- 仅图片可以发送。
- 图片 + 文本可以发送，算 1 条消息。
- 图片上传中不能发送。
- 发送中不能重复点击发送按钮。

## 7. 时间、已读和未读

### 7.1 日期显示

- 当天消息显示 `Today`。
- 昨天及更早显示完整日期，例如 `2025/09/12`。
- 同一天只显示 1 次日期，放在当天第一条消息上方。

### 7.2 时间显示

- 一段连续聊天的开头，在首条消息上方显示时间，例如 `14:32`。
- 若聊天中断超过 10 分钟后重新发消息，再次显示时间。

### 7.3 已读状态

用户发出最新消息后，状态按以下顺序变化：

| 状态 | 含义 | 展示位置 |
| --- | --- | --- |
| `Unread` | 角色尚未开始准备回复 | 用户最新消息附近 |
| `Read` | 角色已开始准备回复 | 用户最新消息附近 |
| `···` | 角色正在输入 | 角色气泡位置 |

### 7.4 未读提示

- Chat 列表中，每个角色会话卡显示该会话未读数。
- 未读数使用粉色圆形角标。
- 底部导航 Chat tab 在全局存在未读时显示红点。
- 用户进入某角色对话页后，该角色未读数清零。

## 8. 语言和翻译规则

本项目使用用户在 Me 中设置的 Default Language 作为全局文本语言。

| 对象 | 语言规则 |
| --- | --- |
| 角色文本回复 | 跟随用户 Default Language |
| 角色语音声音 | 始终为角色母语 |
| 角色语音文本内容 | 跟随用户 Default Language |
| 角色电话声音 | 始终为角色母语 |
| 角色电话文本内容 | 跟随用户 Default Language |
| 用户输入 | 用户可用任意语言输入 |

如果用户修改 Default Language：

- 新产生的角色文本回复跟随新语言。
- 新产生的语音 / 电话文本内容跟随新语言。
- 历史语音 / 电话的文本内容可按当前 Default Language 重新展示。

## 9. 角色语音消息

### 9.1 功能说明

角色语音消息是角色主动发来的音频消息，不是用户录音功能。

用户不能手动要求系统一定生成语音，也不能点击某个按钮让角色立即发语音。语音是否出现，由用户消息带来的情绪强度和后端判断决定。

### 9.2 触发规则

角色语音由以下因素决定：

- 用户消息触发较明显的情绪波动。
- 当前角色允许在此时发语音。
- 后端 prompt 和判断逻辑认为适合用语音回应。

具体 prompt 和情绪判断由后端控制。PRD 只定义前端体验和业务结果。

### 9.3 展示规则

语音消息在消息流中展示为角色气泡：

- 左侧为角色头像。
- 气泡内有可点击语音条。
- 语音条展示播放按钮、播放动效或进度、语音时长。
- 语音条下方展示文本内容。
- 语音条播放的声音是角色母语。
- 语音条下方文本语言跟随用户 Default Language。
- 声音和文本表达的是同一段内容，只是语言不同。
- 例如角色是韩国人、用户 Default Language 是中文时，用户点击语音条后听到角色用韩语说话，语音条下方看到对应的中文文本。
- 点击语音条播放角色母语声音，语音条需要进入播放动效。
- 播放中再次点击可暂停。
- 播放结束后回到可重播状态。

### 9.4 边界

- 语音加载失败时，语音条显示 retry 或 Toast，文本内容仍可展示。
- 没有音频但有文本时，降级为角色文本消息。
- 没有文本但有音频时，应展示临时文本占位，例如 `Translating...`。
- Scene 进行中、OB、Scene 对话内不触发普通 Chat 语音消息。

## 10. 角色来电 Voice Call

### 10.1 功能说明

Voice Call 是 App 内的角色模拟来电，不是真实手机电话。

它不拨打用户手机号，不进入系统电话，不产生真实运营商通话，不需要用户提供电话号码。它是角色侧在 App 内触发的一段全屏语音互动。

用户不能主动拨打角色电话。电话只能由角色侧触发。

### 10.2 触发规则

角色来电由以下因素决定：

- 用户消息出现强关键词，例如“打电话”“给我打电话”“call me”。
- 用户消息触发高情绪强度。
- 当前角色允许在此时来电。
- 后端 prompt 和判断逻辑认为适合发起电话。

具体 prompt、关键词匹配和情绪判断由后端控制。

### 10.3 来电流程

1. 用户发送消息。
2. 消息流中角色侧先展示 `···` 动效，表示角色正在准备回应。
3. 后端判断是否触发电话。
4. 如果不触发电话，角色按普通文本或语音规则回复。
5. 如果触发电话，前端判断用户当前是否仍在该角色 Chat 对话页。
6. 如果用户仍在该角色 Chat 对话页，App 展示全屏来电页。
7. 如果用户已退出 App、切换到其他页面、切换到其他角色 Chat 或不在该角色 Chat 对话页，则不弹来电页，直接在该角色消息流中生成 `Call Ended` 电话记录。
8. 用户接听后进入通话播放页。
9. 用户拒接或 30 秒无操作，生成 `Call Ended` 电话记录。
10. 用户接听后挂断，生成 `Call Ended` 电话记录。
11. 用户接听后完整听完，生成 `Call Ended` 电话记录。
12. 电话流程结束后回到 Chat 对话页。

### 10.4 全屏来电页

来电触发后，当前页面被全屏来电页覆盖。

页面包含：

- 角色大海报模糊背景
- 深色蒙层
- 角色头像
- 角色昵称
- 文案 `Incoming Voice Call`
- 接听按钮
- 挂断 / 拒接按钮
- 响铃动效
- 底部 AI 提示文案：

```text
This content is AI-generated.
```

视觉要求：

- 来电页要像“角色正在打给我”，但不能像系统真电话到让用户误解。
- 背景使用角色图片铺满大海报，但必须做模糊处理并加蒙层，不能影响头像、姓名、按钮和提示文案识别。
- 接听和拒接按钮位置稳定，避免误触。
- 响铃期间可有头像轻微呼吸、背景柔光或按钮脉冲。
- 来电页属于 App 内模拟来电界面，不调用系统电话 UI。

### 10.5 响铃时间

- 前台来电响铃 30 秒。
- 30 秒内用户接听，进入通话播放页。
- 30 秒内用户点击挂断 / 拒接，生成 `Call Ended` 电话记录。
- 30 秒无操作，自动挂断，并生成 `Call Ended` 电话记录。
- App 在后台、用户退出 App、用户切换到其他页面或用户不在该角色 Chat 对话页时，不弹全屏来电页，直接在该角色 Chat 中生成 `Call Ended` 电话记录。

### 10.6 接听后通话页

用户接听后进入全屏通话播放页。

页面包含：

- 角色大海报模糊背景和深色蒙层
- 角色头像
- 角色昵称
- 正向计时，例如 `00:12`
- 角色母语声音播放
- 固定字幕区域
- 字幕文本，语言跟随 Default Language
- 挂断按钮
- 底部 AI 提示文案 `This content is AI-generated.`

规则：

- 通话不是实时多人通话，本质是角色来电语音内容播放。
- 通话进行中计时为正向计时。
- 计时从 1 秒开始向上走。
- 角色声音为角色母语。
- 字幕文本语言跟随用户 Default Language。
- 声音和字幕表达的是同一段内容，只是语言不同。
- 字幕按句展示在固定区域内。
- 角色说下一句时，字幕自动跟随切换或滚动到当前句。
- 用户可以在字幕区域内上下滑动，查看已经出现过的句子。
- 用户可随时点击挂断。
- 用户挂断后回到 Chat 对话页，并生成 `Call Ended` 记录。
- 如果音频完整播放结束，也生成 `Call Ended` 记录。

### 10.7 Chat 中的电话记录

只要电话被触发，无论用户是否接听，Chat 消息流中都必须出现电话记录。

电话记录展示在角色侧，样式为角色气泡：

- 电话 icon
- 文案 `Call Ended`
- 这通电话内容本身的完整时长

统一规则：

| 状态 | Chat 记录文案 | 电话时长 | 是否可回放 |
| --- | --- | --- | --- |
| 接听后结束 | `Call Ended` | 电话内容完整时长 | 可以 |
| 接听后中途挂断 | `Call Ended` | 电话内容完整时长 | 可以 |
| 音频播放完成 | `Call Ended` | 电话内容完整时长 | 可以 |
| 用户点击挂断 / 拒接 | `Call Ended` | 电话内容完整时长 | 可以 |
| 30 秒无操作自动挂断 | `Call Ended` | 电话内容完整时长 | 可以 |
| App 后台 / 用户不在该角色 Chat 页 | `Call Ended` | 电话内容完整时长 | 可以 |

点击电话记录后进入通话回放页。即使用户当时没有接听，也可以回听完整电话内容。

回放规则：

- 回放不再响铃。
- 回放页面展示角色头像、角色昵称、电话文本内容和播放控制。
- 回放页面左上角有返回按钮。
- 回放的计时使用倒计时，和正在通话时的正向计时区分。
- 回放字幕同样使用固定区域，文本语言跟随用户 Default Language。
- 用户可在字幕区域内上下滑动查看文本。
- 回放结束后仍停留在可重播状态。

### 10.8 边界

- 电话触发失败时，降级为普通文本或语音回复。
- 电话音频加载失败时，电话记录保留，点击后提示加载失败，可重试。
- 同一时间只允许 1 个角色来电。
- Scene 进行中、OB、Scene 对话内不触发普通 Chat 电话。
- 用户正在某角色 Scene 进行中时，该角色普通 Chat 被锁定，不应再触发该角色普通来电。
- 电话等待过程中用户离开当前角色 Chat 页时，不再弹出全屏来电页，只生成 `Call Ended` 记录。

## 11. Chat 列表页

### 11.1 页面目的

让用户看到所有已添加角色的会话状态，并快速进入某个角色的聊天。

Chat 列表应该像关系入口，不像客服会话列表。未读、流程插入消息、Scene 进行中都要明显但克制地展示。

### 11.2 页面结构

页面包含：

- 顶部标题 `Chat`
- 右上角加联系人入口
- 会话列表
- 底部导航 Home / Chat / Scene / Me

Chat tab 高亮。全局有未读时，Chat tab 显示红点。

### 11.3 会话卡内容

每张会话卡包含：

- 角色头像
- 角色昵称
- 最后一条消息预览
- 最后一条消息时间
- 未读数角标

消息预览规则：

| 最后一条消息类型 | 预览文案 |
| --- | --- |
| 文本 | 展示实际内容，超长截断 |
| 图片 | `Photo` |
| 语音 | `Voice Message` |
| 电话 | `Voice Call` |
| Scene 邀请卡片 | `Scene Invitation` |
| Scene 进行中 | `[Scene in progress]` |

### 11.4 排序规则

- 按最后一条消息时间倒序排列。
- 最新消息在最上方。
- Scene 进行中的角色仍按其最新会话时间参与排序。

### 11.5 交互规则

- 点击会话卡，进入该角色 Chat 对话页。
- 左滑会话卡，出现清空聊天记录入口。
- 点击右上角加联系人入口，进入 Discover Members。

### 11.6 状态处理

| 状态 | 处理 |
| --- | --- |
| 加载中 | 使用会话卡骨架屏 |
| 拉取失败 | Toast 提示，支持下拉重试 |
| 异常空列表 | 提示去 Discover Members 添加角色 |
| 全部无未读 | 不显示 Chat tab 红点 |

正常情况下，用户完成 OB 后至少有 1 个会话。

## 12. Discover Members

### 12.1 页面目的

让用户添加更多角色，扩大关系网络。

这不是通讯录，不是普通“添加联系人”，而是把新的角色带入用户的关系世界。

### 12.2 页面结构

页面包含：

- 顶部返回按钮
- 标题 `Discover Members`
- 未添加成员网格
- 成员卡片

每张成员卡片包含：

- 角色图
- 角色姓名
- 角色介绍
- `Add Friend` 按钮

### 12.3 展示规则

- 只展示尚未添加的成员。
- 已添加成员不再出现在 Discover Members。
- 全部添加后显示空状态文案：

```text
You've added everyone.
```

### 12.4 加好友流程

1. 用户点击 `Add Friend`。
2. 按钮进入 loading。
3. 页面展示 `Adding friend...` 过渡。
4. 如果添加成功，展示 Toast：`Added {character_name} as friend`。
5. 成功后返回 Chat 列表。
6. 新角色会话出现，并带未读开场白。
7. Home / Scene 同步新增该角色。
8. 如果添加失败，Toast 报错，停留在 Discover Members。

### 12.5 过渡动效

- 点击 `Add Friend` 后，展示约 3 秒的添加好友过渡感。
- 可使用粉色 loading、背景轻微虚化、文案 `Adding friend...`。
- 过渡期间禁止重复点击任何 `Add Friend`。
- 成功后自动返回 Chat 列表。

### 12.6 边界

| 状态 | 处理 |
| --- | --- |
| 角色图未加载 | 展示占位图或骨架 |
| 添加失败 | Toast 提示，按钮恢复可点 |
| 重复点击 | 只处理第一次点击 |
| 全部已添加 | 展示空状态 |

## 13. Chat 对话页

### 13.1 页面目的

让用户和单个角色进行日常聊天，并承接语音、电话、Scene 邀约和记忆回流。

它应该像一条持续存在的私密关系线，而不是一次性问答窗口。

### 13.2 页面结构

页面包含：

- 顶部返回按钮
- 顶部角色头像
- 角色昵称
- 副标题 `Chat · Remote mode`
- 右上角 Scene 按钮
- 消息流
- 底部输入区

### 13.3 顶部交互

- 点击返回按钮，回到 Chat 列表。
- 点击消息流中任意角色头像，进入 Chat Settings。
- 点击右上角 Scene 按钮，进入 Scene 模块，并将当前角色排在选角优先位置。

### 13.4 消息流视觉

- 背景使用该角色聊天背景。
- 默认背景来自角色默认资源。
- 用户可在 Chat Settings 中修改该角色聊天背景。
- 角色气泡在左侧，使用深色或半透明气泡，并显示角色头像。
- 用户气泡在右侧，使用粉色系气泡，并显示用户头像。
- 用户头像来自 Me 模块；如果用户在 Me 修改头像，Chat 中用户消息气泡旁的头像同步更新。
- 时间、已读、未读、`···` 状态清晰但不抢戏。

### 13.5 底部输入区

输入区包含：

- 图片 icon
- 文本输入框
- 发送按钮

Placeholder：

```text
Message...
```

交互规则：

- 点击图片 icon，可选择相册或现拍。
- 选定图片后，图片预览显示在输入框上方。
- 用户可删除已选图片。
- 用户可在图片旁补充文字。
- 点击发送后，输入区暂时禁用，等待角色回复完成。

### 13.6 失败和重试

| 状态 | 处理 |
| --- | --- |
| 文本发送失败 | 用户消息旁展示 retry |
| 图片上传失败 | Toast 提示，保留输入内容 |
| AI 回复超时 | 用户消息旁展示 retry |
| 用户取消选图 | 回到普通输入态 |
| 网络断开 | Toast 提示，可重试 |

## 14. Scene 在 Chat 中的表现

Chat 需要展示 Scene 的入口、邀请和进行中状态，但 Scene 具体玩法以 Scene 模块 PRD 为准。

### 14.1 用户从 Chat 发起 Scene

用户点击某角色 Chat 右上角 Scene 按钮后：

- 进入 Scene 模块。
- 当前角色在选角时优先出现。
- 用户选择地点和事件后，回到该角色 Chat 对话页。
- 输入框上方出现地点 / 事件预览条。
- 输入框内可出现预设邀请文案。
- 用户发送后，Chat 中插入 Scene 邀请卡片和用户邀请文案。
- 角色接受后，消息下方出现 `Go Now` 按钮。
- 用户点击 `Go Now` 后进入 Scene。

### 14.2 角色触发 Scene 邀请

角色可通过 Trigger 系统在 Chat 中发起 Scene 邀请。

表现为：

- 角色先发一条邀请语音或邀请消息。
- 随后出现 Scene 邀请卡片。
- 卡片下方有 `Accept` / `Decline` 按钮。
- 用户接受后进入 Scene。
- 用户拒绝后按钮消失，角色可发送拒绝回应。
- 24 小时未操作，邀请过期。

### 14.3 Scene 进行中时 Chat 锁定

某角色 Scene 进行中时，该角色普通 Chat 页面出现进行中状态。

Chat 列表表现：

- 该角色会话卡消息预览显示 `[Scene in progress]`。
- 可使用粉色或高亮文字区别普通消息。

Chat 对话页表现：

- 顶部栏下方出现 Scene 进行中条。
- 进行中条展示角色头像、`Scene in progress`、地点名和事件名。
- 点击进行中条，恢复进入该 Scene。
- 聊天流中可出现一条灰色旁白：

```text
You have arrived at {location_name}, the story is progressing.
```

- 底部输入框锁定。
- Placeholder 变为：

```text
Scene is in progress
```

规则：

- 当前角色普通 Chat 被锁定。
- 用户要继续和该角色互动，需要进入 Scene。
- 其他角色普通 Chat 不受影响。
- 同一时间只允许 1 个 Active Scene。

## 15. Chat Settings

### 15.1 页面目的

让用户管理单个角色在自己 App 中的展示方式，并提供举报入口。

这里改的是角色资料，不是用户资料。用户自己的昵称、头像、语言等设置归 Me 模块。

### 15.2 入口

入口为 Chat 对话页消息流中的任意角色头像。

用户点击角色头像后进入 Chat Settings。

### 15.3 页面结构

页面包含：

- 返回按钮
- 标题 `Chat Settings`
- 当前角色大头像
- 当前角色昵称
- 设置菜单
- `Report Character` 按钮

### 15.4 设置项

| 设置项 | 行为 | 影响范围 |
| --- | --- | --- |
| `Change Nickname` | 修改角色昵称 | Chat 列表、Chat 对话页、Home、Scene 等所有展示该角色昵称的位置 |
| `Change Chat Avatar` | 修改角色头像 | Chat 列表、Chat 对话页、Scene 等所有展示该角色头像的位置 |
| `Change Chat Background` | 修改该角色聊天背景 | 仅该角色 Chat 对话页背景 |
| `Change Home Poster` | 修改该角色 Home 海报 | Home 中该角色海报 |

### 15.5 修改规则

- 修改昵称时，昵称不能为空。
- 修改图片时，用户可从相册选择或拍摄。
- 修改图片后可恢复默认。
- 恢复默认时使用角色出厂资源。
- 修改成功后展示 Toast。
- 修改失败后展示 Toast，并保留原设置。

### 15.6 边界

| 状态 | 处理 |
| --- | --- |
| 昵称为空 | 不允许保存，提示必填 |
| 图片上传失败 | Toast 提示，保留原图 |
| 用户取消选图 | 返回设置页，不改变内容 |
| 恢复默认失败 | Toast 提示 |

## 16. 举报

### 16.1 入口

举报入口有两个：

- Chat Settings 底部 `Report Character`
- 长按角色消息后的 `Report`

### 16.2 举报弹窗

弹窗包含：

- 标题 `Report Character`
- 副标题 `Please select a reason`
- 举报原因单选列表
- `Submit` 按钮
- `Cancel` 按钮

举报原因：

1. `Politically sensitive`
2. `Sexual / vulgar`
3. `Verbal abuse`
4. `False / misleading`
5. `Other`

### 16.3 交互规则

- 用户必须选择一个原因后才能提交。
- 点击 `Submit` 后视为提交成功。
- 成功后 Toast：

```text
Report submitted
```

- 点击 `Cancel` 关闭弹窗，不提交。
- 提交失败时 Toast 提示，可再次提交。

## 17. 消息操作

用户长按单条消息后，出现消息操作菜单。

当前只支持单条操作，不支持多选。

| 操作 | 适用范围 | 是否二次确认 | 结果 |
| --- | --- | --- | --- |
| `Copy` | 文本类消息 | 否 | 复制文本，Toast：`Copied` |
| `Delete` | 所有类型消息 | 是 | 删除该条消息，仅影响显示层 |
| `Report` | 角色消息 | 否 | 打开举报流程或直接提交后 Toast |

### 17.1 删除说明

删除单条消息只影响用户当前看到的聊天记录，不改变角色关系、记忆系统、Scene 记录或 Home 拍立得。

## 18. 清空聊天记录

### 18.1 入口

Chat 列表中，用户左滑某个角色会话卡，出现清空入口。

点击清空入口后弹出二次确认弹窗。

### 18.2 清空范围

清空内容包括：

- 该角色文本消息
- 该角色用户图片消息
- 该角色语音消息
- 该角色电话记录
- 该角色 Scene 邀请在 Chat 中的消息记录

清空不影响：

- Chat 列表中的该角色会话卡
- 好友关系
- Home 拍立得
- Home 海报
- Scene 历史拍立得
- 角色昵称
- 角色头像
- 角色聊天背景
- 角色 Home 海报设置

### 18.3 清空后表现

- 该角色仍保留在 Chat 列表。
- 进入该角色对话页后，聊天内容为空。
- 该角色未读数清零。
- 该角色 Home 和 Scene 中的内容不消失。

## 19. 内容未准备好时的处理

如果内容团队暂时还没给最终文案、图片、角色资源或 prompt 细节，开发可以先用临时内容搭建页面和流程。

开发期允许：

- 角色头像没给：先用占位头像。
- 角色聊天背景没给：先用默认暗色背景。
- Discover Members 角色介绍没给：先用临时介绍。
- OB 流程插入消息没给：先用临时消息，具体规则以 OB 模块为准。
- 加好友开场白没给：先用临时开场白。
- 语音音频没返回：降级展示文本消息。
- 电话音频没返回：降级展示文本或语音消息。
- Scene 卡片图没给：先用场景占位图。

但上线前，正式内容必须补齐。

## 20. 不希望出现的体验

- 用户以为 Voice Call 是真实手机电话。
- 用户可以主动给角色打电话。
- 用户可以主动录语音发给角色。
- 角色电话没有响铃过程，突然插入一条电话记录。
- 电话记录出现 `Missed Call`，导致和统一 `Call Ended` 规则不一致。
- 未接或拒接后无法回听完整电话内容。
- 语音只有音频，没有文本内容。
- 语音条不可点击，或者点击后没有播放动效。
- 语音声音和下方文本不是同一段内容。
- 电话声音和字幕不是同一段内容。
- 角色母语声音和 Default Language 文本规则混乱。
- 用户连续发多条消息，角色回复顺序错乱。
- 清空聊天记录后，好友关系或 Home 拍立得也消失。
- Scene 进行中时，用户还能在同一角色普通 Chat 里继续聊天。
- 其他角色因为某个角色 Scene 进行中而被错误锁住。
- Chat 列表像客服工单列表，缺少亲密关系感。

## 21. 验收标准

### 21.1 Chat 列表

- OB 完成后至少出现首位角色会话。
- 首位角色会话能展示 OB 流程插入的未读消息。
- Chat tab 有未读红点。
- 会话按最后消息时间倒序。
- 不同消息类型有正确预览文案。
- 左滑会话卡可以触发清空聊天记录入口。

### 21.2 Discover Members

- 只展示未添加成员。
- 点击 `Add Friend` 后进入添加过渡。
- 添加过程中不能重复点击。
- 添加成功后返回 Chat 列表。
- 新角色会话出现并带未读开场白。
- 全部添加后展示 `You've added everyone.`。

### 21.3 Chat 对话页

- 用户可以发送文本。
- 用户可以发送图片。
- 用户可以发送文本 + 图片。
- 用户不能主动发送语音。
- 用户不能主动打电话。
- 用户消息气泡旁展示用户头像。
- Me 修改用户头像后，Chat 用户头像同步更新。
- 每次只能发送 1 条消息。
- 角色回复完成前输入区不可继续发送。
- AI 失败或超时时可以重试。

### 21.4 语音消息

- 语音只由角色发送。
- 语音消息展示语音条、时长和文本内容。
- 语音声音为角色母语。
- 文本内容语言跟随 Default Language。
- 语音声音和文本表达同一段内容，只是语言不同。
- 点击语音条可以播放、暂停、重播。
- 点击播放时语音条有播放动效。
- 语音失败时有降级或重试处理。

### 21.5 Voice Call

- 电话只由角色触发。
- 用户不能主动拨号。
- 用户消息发送后，等待电话判断期间先展示角色 `···` 动效。
- 电话触发后出现全屏来电页。
- 来电页包含接听和拒接按钮。
- 来电页背景是角色大海报模糊背景 + 蒙层。
- 来电页展示角色头像和角色名字。
- 来电页底部展示 `This content is AI-generated.`。
- 前台响铃 30 秒。
- 接听后进入通话播放页。
- 拒接或超时后生成 `Call Ended`。
- 接听后挂断或播放完成生成 `Call Ended`。
- 用户离开该角色 Chat 页后，不弹来电页，直接生成 `Call Ended`。
- 只要电话被触发，Chat 中都形成 `Call Ended` 电话记录。
- 电话记录展示电话 icon、`Call Ended` 和电话内容完整时长。
- 电话记录可点击回放。
- 未接、拒接、接听后挂断、完整听完都可以回放完整电话内容。
- 电话声音为角色母语。
- 电话文本内容语言跟随 Default Language。
- 电话声音和字幕表达同一段内容，只是语言不同。
- 接听后通话计时为正向计时。
- 回放页计时为倒计时。
- 通话页和回放页都有固定字幕区域，字幕可自动跟随，也可手动上下滑动查看。

### 21.6 Scene 联动

- Chat 右上角 Scene 按钮可以进入 Scene 模块。
- 从某角色 Chat 进入 Scene 时，该角色优先展示。
- Scene 邀请卡片可以插入 Chat 消息流。
- 角色 Trigger 邀请可在 Chat 中展示。
- Scene 进行中时，该角色 Chat 输入框锁定。
- Scene 进行中条可点击回到 Scene。
- 其他角色 Chat 不被锁定。

### 21.7 Chat Settings 和举报

- 点击角色头像进入 Chat Settings。
- 修改昵称后，全局该角色昵称同步变化。
- 修改头像后，全局该角色头像同步变化。
- 修改聊天背景后，该角色 Chat 背景变化。
- 修改 Home 海报后，Home 对应角色海报变化。
- 举报弹窗可选择原因并提交。
- 提交成功后 Toast 显示 `Report submitted`。

### 21.8 清空聊天记录

- 左滑会话卡可触发清空。
- 清空前有二次确认。
- 清空后该角色聊天内容为空。
- 清空后该角色仍在 Chat 列表。
- 清空后好友关系不消失。
- 清空后 Home 拍立得不消失。
- 清空后角色设置不消失。

## 22. 给开发的自由度

开发可以自行决定：

- 接口如何命名。
- 数据字段如何命名。
- 消息状态如何存储。
- 电话音频如何播放和缓存。
- 图片上传如何实现。
- 本地缓存和服务端同步如何分工。
- retry、loading、toast 的具体组件实现。

但最终体验必须符合本文定义的业务规则、页面表现、交互流程、动效要求和验收标准。
